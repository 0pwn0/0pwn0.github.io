ESC15 Cheatsheet - Vietnamese Language

Created2025-11-28|Updated1970-01-01|Cheatsheet
|Post Views:

Trước tiên ta sẽ nói về cách dump credentials (như NTLM hash hoặc cert để escalate) theo ESC15 (một kỹ thuật privilege escalation mới trong ADCS - Active Directory Certificate Services, được phát hiện năm 2024, CVE-2024-49019, còn gọi là EKUwu). ESC15 khai thác các Certificate Template phiên bản Schema 1 (V1 templates) để inject arbitrary Application Policies (EKU/OID tùy ý), cho phép enroll certificate cho user/service account khác (thường là DA - Domain Admin), sau đó dump hash từ cert đó.

Lưu ý quan trọng:

  • ESC15 KHÔNG phải là local dump như Rubeus (chỉ dump từ memory LSASS). Đây là domain escalation qua ADCS, yêu cầu:
    • Quyền low-priv (Domain User hoặc Machine account).
    • Có ADCS server với template V1 vulnerable (không có MS patch trước Nov 2024; sau đó cần kiểm tra patch).
    • Tool chính: Certipy (Python tool, fork từ ly4k/Certipy).
  • Nếu CA đã patch hoặc template được duplicate lên V2, attack sẽ fail.
  • Sau khi enroll cert thành công, bạn có thể dùng Rubeus hoặc Mimikatz để export private key và dump NTLM hash (qua pass-the-cert hoặc DCSync).
  • Bypass AV/EDR: Chạy Certipy qua Cobalt Strike beacon hoặc obfuscate; kiểm tra EDR logs cho cert enrollment.

Bước 1: Kiểm tra vulnerability (find vulnerable templates)

Chạy Certipy để enum ADCS templates và tìm V1 templates cho phép enroll (pMSRAuth, Client Auth EKU, etc.).

  • Output sẽ liệt kê templates như “User” hoặc custom V1 với msPKI-Certificate-Name-Flag=0x1 (enrollable), và vulnerable to ESC15 nếu SchemaVersion=1.
  • Tìm template có pKIEnrollmentFlag=0x00000020 (published) và EKU cho phép Client Authentication.

Nếu không có template V1, duplicate một cái (nếu có quyền) để tạo V2 an toàn hơn, nhưng cho attack thì dùng V1.

Bước 2: Exploit ESC15 - Enroll certificate cho target user (ví dụ: DA account)

Sử dụng flag --application-policies để inject EKU tùy ý (arbitrary policy), bypass check. Giả sử target là dauser@domain.com (thay bằng user thật), template là “User” (V1 default).

  • -target / -alt: Chỉ định user để enroll cert dưới tên họ (impersonate).
  • -application-policies <OID>: Key của ESC15 - inject EKU arbitrary (ví dụ OID cho Smart Card Logon hoặc Kerberos).
  • Nếu thành công, bạn có file .pfx chứa cert + private key của DA.

Bước 4: Cleanup & Persistence

  • Xóa cert khỏi CA: certipy account del -u 'lowprivuser' -target 'dauser'.
  • Nếu muốn persist: Dùng cert để add shadow creds hoặc backdoor.

Mitigation (cho Blue Team)

  • Patch: Áp dụng MS patch Nov 2024 cho CVE-2024-49019.
  • Duplicate tất cả V1 templates lên V2 và unpublish V1.
  • Disable auto-enrollment cho low-priv users.
  • Monitor Event ID 4886/4887 (cert enrollment) với target user mismatch.
